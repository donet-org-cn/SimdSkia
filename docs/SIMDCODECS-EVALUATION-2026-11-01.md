# SimdCodecs 能否接入 SimdSkia：JPEG 值得接入，PNG 需要额外处理

后续状态：用户已授权 .NET 10 与系统压缩例外，完整替换试用另见[接入报告](SIMDCODECS-INTEGRATION-2026-11-01.md)。以下保留替换前独立评估的原始范围和数据，不代表当前生产源码仍未变化。

日期：2026-11-01。比较当前 SimdSkia preview.9 源码与公开 NuGet **Sdcb.SimdCodecs.Jpeg / Png 1.2.0**。
包内 repository commit 为 `02b1f5aab83fee545748801639b12002ee7d2462`；另外查看的 main 为 `99d9e4501d4d7d9608e0d1a4436d58a7648a83ec`，性能不使用 main 自编译版本。
本轮仅新增隔离基准、真实 AOT 探针、报告和证据，**没有更换生产依赖、升级公共目标框架或发布版本**。

结论：JPEG 有明显收益，建议通过 **.NET 10 可选扩展或多目标构建**接入；当前 .NET 8 主库不能直接 PackageReference。
不建议一口气替换全部编解码。PNG 解码更快、编码更省分配且文件更小，但编码更慢，且涉及原生压缩和 ICC 转换边界。
收益对应图片加载/导出；没有测得 Avalonia 控件绘制、GPU、OCR 全链路或应用常驻内存的变化。

## 测量方式

Intel i7-8700K，6 核/12 线程，Windows x64，双方均为 **.NET 10.0.13 Release JIT**，硬件支持 AVX2。
当前 SimdSkia 的 net8.0 程序集也运行在同一个 .NET 10 进程类型中；这不是 net8 vs net10 的跨运行时排名。

两个自制 1920×1080 **不透明 UI / 纹理图案**，不是照片集。双方解码相同压缩字节；输入、源像素在计时前读取。
每场景每后端三个独立串行进程，次序交替；每进程先执行一次，再预热至少 0.5 秒，采样至少 1.2 秒，报告三进程中位数。
全矩阵 **60 个进程**。编译和 AOT 验证在正式计时之前完成，未与基准并行。

解码双方返回拥有生命周期的 PixelBuffer，包含获取/清零（候选公开 Rent API）和释放成本；未用永久复用缓冲的内核数字冒充应用调用。
编码双方返回完整新 byte[]。JPEG 同为 quality=90、4:4:4、baseline、默认 Huffman；没有用 4:2:0 降低编码工作量。
PNG 同为 Optimal、单片串行，但过滤器/压缩器不同，输出体积也必须一起看。

JPEG 解码约 **11.2–40.3 倍**，编码约 **8.8–9.0 倍**；PNG 解码约 **1.6 倍**。
PNG 编码的耗时分别增加约 **33% / 78%**。这些是本机两个合成图案的短时稳态数据，不能声称任意照片或业务应用都按同样比例提升。
当前 JPEG 热路径还有逐像素采样、插值与颜色转换开销，候选行式 SIMD 解码避免了大量工作；速度表本身不证明每个阶段各占多少，未做逐阶段消融归因。

## 分配和内存

输入字节、编码源图、运行时、热缓存包含在进程内存中。分配包含输出数组/适配对象；JPEG 解码候选约 90 B/张，不冒称整个接口零分配。

## 画质、压缩体积、颜色合同

- 两个测速 PNG 解码与源像素逐字节相同；四个 PNG 编码输出用现有解码器交叉回读，也逐字节一致。
- 测速 JPEG 解码双方最大通道差 0–2、RGBA RMSE 0–0.282，没有为了速度降低输出分辨率或改变 4:2:0 输入。
- JPEG 编码同 quality=90 / 4:4:4，交叉回读到相同现有解码器：UI RGB PSNR **47.260→47.869 dB**，纹理 **36.298→36.311 dB**。
  文件大小 **194433→196847 B**、**760644→749217 B**。这是这两个源图和该解码器下的质量诊断，未建立任意 JPEG 编码等价承诺。
- PNG 文件大小 UI **109711→12542 B**，纹理 **6307964→2631876 B**。候选编码较慢但压缩更好，不能只看耗时下结论。
- 现有独立夹具 **41 个**：当前解码 **40 通过、1 个渐进式 CMYK 明确拒绝**；候选直接适配 **40 通过、1 个 Display-P3→sRGB 不通过**。
  候选支持该渐进式 CMYK，是功能增益；候选 PNG 接口保留 ICC 信息，调用方还需要颜色转换。本原型只写入 RGBA，没有执行该转换，
  P3 最大通道误差 **74**、RMSE **9.247**，原门槛 2 / 0.6，未放宽门槛或当作成功。
- 同一组 **41 个候选输出摘要**在默认 SIMD JIT、关闭全部硬件指令的 JIT、实际 Native AOT 下全部一致；这是路径正确性验证，**AOT 速度没有测量**。

## 建议接入方式

1. 保留 net8.0 用户和当前默认编解码。新增 net10.0 可选扩展或多目标条件引用，优先引入 `Sdcb.SimdCodecs.Jpeg 1.2.0`，不必安装所有格式的汇总包。
2. 建立自己的编解码适配，保留输入/解码大小预算、实际尺寸验证、ICC→sRGB、Alpha/stride、异常和 Dispose 合同；暂时让未验证的颜色/元数据路径走原有实现。
3. PNG 先保留 ManagedZlib。若需要候选过滤器，应先验证可注入托管压缩的实现，再重新测速度和体积；本次原生压缩数字不能作为“全 C# PNG”成绩。
4. WebP/TIFF/JPEG2000/JBIG2 可能扩展功能，但本次没有执行这些格式的完整兼容/性能验证，不随本报告宣称支持。
