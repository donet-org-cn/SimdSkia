# SimdSkia 与原生 Avalonia 的内存和 CPU 对照

2026-11-19，在同一台 Win64 机器上比较上一轮本地构建、本轮本地构建和原生 Avalonia。OxyPlot 用来观察实际窗口，另用 Fluent 控件和列表滚动检验通用软件渲染。[逐轮测量、程序指纹与验证记录](evidence/oxyplot-2026-11-19.json)

## OxyPlot 实时窗口

Core i7-12700、GeForce RTX 3060、.NET 10.0.14 工作站 GC、Avalonia 12.1.6、OxyPlot.Avalonia 2.2.0。客户端尺寸 960 × 560，缩放 100%，两条曲线共用固定随机种子，每秒更新一次。SimdSkia 使用 Direct2D，原生使用 Skia/ANGLE D3D11。每组启动三个独立进程，轮换次序。每次预热 10 秒、静置 8 秒、刷新 45 秒，计时结束后再做两次完整 GC。表内为各进程统计值的中位数。

| 指标 | 上一轮本地 | 本轮本地 | 原生 Avalonia |
|---|---:|---:|---:|
| 静置工作集（MiB） | 173.7 | 166.1 | 155.6 |
| 刷新工作集（MiB） | 169.9 | 161.7 | 164.4 |
| 刷新工作集 P95（MiB） | 177.2 | 166.7 | 168.0 |
| 刷新私有工作集（MiB） | 83.5 | 75.0 | 65.1 |
| 刷新私有提交量（MiB） | 134.6 | 126.2 | 145.9 |
| 刷新托管堆（MiB） | 25.26 | 18.38 | 10.83 |
| 完整 GC 后托管留存（MiB） | 14.68 | 7.87 | 3.63 |
| 其中 LOH 留存（MiB） | 6.69 | 1.52 | 0.93 |
| 刷新托管分配（MiB/s） | 1.560 | 1.219 | 0.876 |
| 45 秒自然 GC，Gen 0 / 1 / 2 | 6 / 3 / 1 | 5 / 2 / 1 | 3 / 1 / 0 |
| 进程 CPU（ms/更新），中位数［范围］ | 32.3［29.5–33.7］ | 28.1［27.4–31.9］ | 32.6［27.8–33.0］ |

每个进程都完成了 45 次曲线更新。相较上一轮，本轮每秒分配下降 22%，完整 GC 后 LOH 下降 77%。本轮刷新工作集的三次结果在 161.3–163.2 MiB，原生在 158.8–165.0 MiB。两者的工作集与 CPU 测量范围均有重叠。本轮私有工作集仍比原生高 9.9 MiB，分配速率仍高 39%。

工作集是进程驻留在物理内存中的页，私有工作集只计进程独占的驻留页。私有提交量包括已提交但当时未驻留的页。刷新分配速率来自全进程托管分配计数。大对象堆（LOH）留存已扣除碎片。

同一示例早先对正式 NuGet 0.1.9 的独立四组测试每次刷新 60 秒，中位工作集为 290.1 MiB，分配为 37.79 MiB/s，完整 GC 后 LOH 为 20.18 MiB。已核对当时加载的七个渲染程序集与发行包的字节一致。这一组用于观察从正式版到本地构建的变化，采样时长与上表不同。

## 分配和 GC 来自哪里

- 抗锯齿裁剪和控件阴影原先会为大片相同的扫描行保留整块像素。现在只存一行相同数据，阴影保留完整的高斯采样边缘，Direct2D 分块上传。独立的 30 秒 EventPipe 跟踪中，上一轮采到的 1.49 MiB 大对象分配都来自裁剪遮罩，本轮大对象分配采样为零。[裁剪遮罩生成](../src/SimdSkia.Cpu/RasterCanvas.Sampling.cs) · [控件阴影](../src/SimdSkia.Avalonia/DrawingContext.Effects.cs)
- 轴线和网格的虚线轮廓改用紧凑的矩形表示，小轮廓合并可复用临时存储。字形绘制也减少了中间命令和像素副本。描边的采样分配从 16.56 降到 8.94 MiB。剩余热点包括 `Geometry.CreateStroke` 中 Clipper 的顶点、活动边和坐标数组，以及 Avalonia 建立合成视觉对象的分配。[描边轮廓生成](../src/SimdSkia.Avalonia/Geometry.cs) · [GPU 窗口字形绘制](../src/SimdSkia.Avalonia.Gpu/WindowGpuCanvas.cs)
- 本轮跟踪在约 20.9 秒记录到一次后台 Gen 2，运行时给出的原因是 `AllocSmall`。它与计时结束后的手动 GC 分开统计。20 秒刷新后的独立堆快照中，`PathSegment[]` 从 1,556,656 降到 207,048 字节，`byte[]` 总量从 12.97 降到 5.00 MiB。EventPipe 数值为采样权重，堆快照数值为存活对象大小。
- 对本轮 20 秒快照中全部 16 个至少 85,000 字节的存活对象追踪引用，10 个字体表数组共 1.09 MiB，3 个空闲像素缓冲区共 0.34 MiB，2 个被 Direct2D 图像缓存引用的像素数组共 0.34 MiB，另有一个 0.09 MiB 的整数数组。

## 通用控件、滚动和 NativeAOT

使用 Avalonia 12.1.5 和相同的固定中文字体，发布 Win64 NativeAOT，优化选项为 `Speed`。两边都使用 Win32 软件渲染，绘制 1000 × 720 的 `RenderTargetBitmap`，开启完整组透明度。每个场景轮换三组，预热 2 秒，按 60 Hz 测量 4 秒。[控件基准程序与测量口径](../examples/AvaloniaAot/README.md)

| 场景和指标 | 上一轮 | 本轮 | 原生 Avalonia |
|---|---:|---:|---:|
| Fluent 控件绘制耗时（ms/帧） | 1.89 | 1.80 | 4.21 |
| Fluent 控件托管分配（KiB/帧） | 3.97 | 3.97 | 7.82 |
| Fluent 控件工作集（MiB） | 66.2 | 66.1 | 57.7 |
| 列表滚动绘制耗时（ms/帧） | 1.23 | 1.21 | 1.26 |
| 列表滚动托管分配（KiB/帧） | 5.43 | 5.45 | 12.86 |
| 列表滚动工作集（MiB） | 59.1 | 59.0 | 61.6 |

本轮控件、滚动的进程 CPU 中位数分别为 2.99、2.66 ms/帧，上一轮分别为 1.24、2.15，原生分别为 7.68、5.01。各引擎三次 CPU 测量波动明显。两种场景本轮的 GC 后托管留存分别为 17.45、13.40 MiB，原生为 2.52、1.65 MiB。托管堆指标只覆盖各自交给 .NET 管理的内存。

本轮 EXE 为 25.137 MiB，比上一轮增加 4 KiB，原生 EXE 为 18.700 MiB。含字体、原生依赖、XML 和许可证且排除 PDB 的完整发布目录分别为 31.310 和 41.158 MiB。

## 绘制正确性

从真实 Direct2D 窗口回读首帧和一次固定更新后的画面，两帧分别与上一轮逐像素一致，每帧 537,600 个像素。更新前后的哈希不同，两条曲线均已绘出。另有 114 个瓦片、效果和阴影场景与上一轮逐文件一致。Avalonia 控件、Direct2D/Vulkan、字形批绘、标量/SIMD 和数值回归均通过。将发行版 0.1.9 的兼容层与本轮 Core、Cpu 混用，485 项检查也通过。
