# SimdSkia 引擎与 Avalonia 渲染后端性能实测

2026 年 11 月 18 日，本机 Windows x64，Intel Core i7-12700，NVIDIA GeForce RTX 3060，.NET 10.0.14，Avalonia 12.1.5。箭头左侧为已校验的 NuGet 0.1.6，右侧为当前工作树。两边执行同一段应用代码，使用同一字体、像素输入和依赖。独立原生进程使用 Avalonia.Skia、Avalonia.HarfBuzz 与 SkiaSharp 3.119.4。负载来自仓库的独立控件、渲染和编解码测试程序。[每轮数值、像素哈希、包哈希与堆快照摘要](evidence/engine-avalonia-2026-11-18.json)

100% 控件页每帧分配 5,625 → 3,361 B，绘制耗时 0.496 → 0.496 ms。Direct2D 连续更新位图时，120 帧内的 Gen 2 回收 13 → 0 次。固定工作量的绘图与编解码混合测试总分配 339.967 → 339.965 MiB，进程 CPU 4,719 → 4,625 ms。不同负载的收益相差明显。

## 裁剪、描边、阴影与缩放

重复绘制使用同一批不可变几何。稳定描边每次提交 18 条线及 18 个边框，阴影使用 440×268 的矩形，软裁剪结果为 490×288。变化裁剪每次创建一个覆盖值发生变化的新输入，分配包括这个输入。缩放使用带填充的 640×360 像素行。数据为三个独立进程的中位数。

直线和直角边框可复用已展开的轮廓，缓存限制条目数，虚线按当前画笔生成。矩形阴影使用设备像素边界表示裁剪。软裁剪只写一次结果，用整数向量计算抗锯齿覆盖乘积，重复的大交集使用弱引用。画面和缓存释放都有回归覆盖。位图缩放在绘制前计算横向采样坐标，连续的八像素块直接加载，其他坐标仍按映射采样。

每次都变化的软裁剪仍需要新的输入和输出。384 次操作的分配从 423,542 → 282,395 B/次，Gen 2 回收 4 → 5 次。固定输入的零分配结果是预热后复用仍存活交集时的测量值。

## GC 和存活内存来自哪里

四个位图轮换，每次通过 Avalonia 写锁更新 960×720 BGRA，再绘制、等待和读回。0.1.6 的 Direct2D 缓存更新栈会建立一份 2,764,800 B 的整帧内容快照。按 15.7 帧/秒换算约 41.4 MiB/s，与第三方截图的分配量级相符。对方进程的确切调用占比仍需要该次运行的分配栈。候选能按位图写入版本更新 GPU 内容。普通可变像素缓冲可复用比较快照。[Direct2D 位图缓存](../src/SimdSkia.Gpu.Direct2D/Direct2DCanvas.cs) · [Avalonia 位图写锁](../src/SimdSkia.Avalonia/Bitmap.cs)

| CPU ms/帧 | 2.734 | 1.823 |
| 分配 B/帧 | 2,765,322 | 303 |

另对 100% 混合控件页做完整 GC 后抓取存活对象图。0.1.6、当前、原生 Avalonia.Skia 分别存活 19.91、19.91、2.62 MiB 托管对象。当前引擎的一份字体数据为 6,313,832 B。另有四块各 2,880,024 B 的数组，由两个位图、一个帧缓冲渲染目标和一个可复用缓冲池持有。原生引擎的一部分像素与字体资源位于托管堆之外，跨后端比较时应一并读取工作集和私有内存。快照进程在字体表核对后取样，与前表的计时结束时点略有差异。

Avalonia 控件通过 14,013 项断言，硬件 SIMD 和禁用硬件指令各通过 474,448 项精确字节检查。Win64 NativeAOT 运行了 460,078 项采样检查，编解码通过 204,420 项断言。Direct2D、Vulkan、WGL 与 ANGLE 硬件回归通过。116 张控件 PNG、91 份编码器输出及 9 份硬件/标量像素传输文件逐字节一致。性能数字限于这台 Windows x64 机器。GPU 测量包含同步读回，实际桌面交换链、设备刷新率和输入帧率会改变最终表现。

dotnet run -c Release --project benchmarks/AvaloniaGpuParity/Managed -- --backend direct2d --scene scroll --seconds 2.4 --warmup 1 --full-opacity --output artifacts/d2d-scroll
