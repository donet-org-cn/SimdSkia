# 原版与 SimdSkia 性能对比：2026-10-21

最新 Avalonia 实测见 [桌面启动、CPU/GPU 与内存报告](STARTUP-ROUND7-2026-10-22.md)：70 次可见 JIT/AOT 启动、原版与前后 CPU 对照、18 个实际窗口进程。系统字体控件 0.695→0.666 ms/帧、CPU 窗口分配下降约 17%；常驻内存和持续 GPU 性能没有明显改善，画质失败项仍保留。上一轮 [图片采样与画刷缓存报告](OPTIMIZATION-ROUND6-2026-10-22.md) 及本页早期基准保持原始数据，不混用不同轮次的尺寸/DPI/采样间隔。

实际执行：Intel(R) Core(TM) i7-8700K CPU @ 3.70GHz；Microsoft Windows 10.0.26300；.NET 8.0.32 / X64，逻辑 CPU 12。原版包 SkiaSharp 3.119.4。
每种实现 3 个独立进程；每项每进程 5 批，目标每批 70 ms，预热至少 100 ms 且 3 帧，再校准。进程顺序/场景顺序打乱，串行执行。TieredCompilation=0，ReadyToRun=0，ServerGC=False。

主要结论：以 1024×768 为例，以下只列通过画质门槛的场景。表中倍数大于 1 表示 SimdSkia 更慢；未据清屏接近原版推断全引擎性能。

- clear：原版 0.071 ms，Simd SIMD 0.077 ms，为原版耗时的 1.09 倍。
- rectangles：原版 0.207 ms，Simd SIMD 0.254 ms，为原版耗时的 1.23 倍。
- evenodd：原版 0.139 ms，Simd SIMD 0.159 ms，为原版耗时的 1.15 倍。
- rect-aa：原版 0.200 ms，Simd SIMD 0.208 ms，为原版耗时的 1.04 倍。
- png-decode：原版 3.455 ms，Simd SIMD 3.863 ms，为原版耗时的 1.12 倍。

这次只比较同机 CPU 光栅和 PNG。标量/SIMD 切换控制 CPU 清屏、连续像素填充及覆盖率/预乘 Alpha 合成；PNG 独立按硬件调度 SIMD。另以 DOTNET_EnableHWIntrinsic=0 验证完整标量回退。JIT 优化开启，抗锯齿质量不变。

## 解读边界

- 每个‘op’是一整帧工作负载；rectangles/blend 各含 64 个矩形，chinese 含 4 行，其余 1 项。除 clear 和 codec 外，每帧含同样的清屏。对象/字体/图像准备、JSON、像素核查不在计时内；绘制产生的分配及实际 GC 在计时内。固定场景允许正常复用缓存；额外 curve-changing/chinese-changing 场景每帧移动 1/16 像素、97 个位置循环，超过 64 项缓存容量，强制覆盖率/文字缓存持续未命中。变化场景像素 gate 检查 frame=0；变化位置另外由冻结渲染器随机测试检查。
- CPU RGBA8888/Premul、连续 stride、同尺寸/画笔/命令/字体。PNG 解码共享原版生成的相同压缩输入，双方输出 RGBA8888/Unpremul。
- PNG 编码像素虽相同，原版压缩与 SimdSkia stored 块不同，必须同时看输出字节，不能据时间宣布压缩效率优势。
- AA/字体必须检查本轮相同尺寸的像素 gate；失败的时间保留为诊断数据。未提高容差，也未降低画质。
- B/op 是线程托管分配，不含 native malloc。private/working set 是整个进程，包含 runtime、native/font caches 和先前场景，不能当纯渲染缓冲区内存公平排名；peak working set 是进程历史峰值。完整分配、GC 和内存字段在 CSV/JSON。
- P95 是实际单帧延迟，包含 GC/调度抖动；耗时列是批均值中位数，两者定义不同。原始 ticks 也包含两次计时读取的微小共同开销。
- 样本不控制 OS power plan/Turbo/其他用户进程，不给全引擎或所有硬件的优势承诺。
